CASOS DE TESTE

| ID | Título | Tipo | Critério de Aceitação Relacionado | Passos Resumidos | Resultado Esperado |
|----|--------|------|-----------------------------------|------------------|--------------------|
| TC01 | Enviar mensagem válida pelo formulário de contato | positivo | 2 | Abrir a página inicial, preencher nome, assunto e demais campos obrigatórios com dados válidos e enviar. | A página exibe `Thanks for getting in touch <nome>!`. |
| TC02 | Comparar contador antes e depois do envio | positivo | 1, 3 | Entrar no painel, anotar o contador de Messages, enviar uma mensagem válida como visitante e consultar o painel novamente. | O contador aumenta exatamente uma unidade. |
| TC03 | Encontrar mensagem enviada na caixa de mensagens | positivo | 4 | Enviar uma mensagem válida, entrar no painel e abrir Messages. | A lista contém o nome do remetente e o assunto enviados. |
| TC04 | Solicitar login ao abrir Messages após logout | positivo | 5 | Entrar no painel, sair, tentar abrir diretamente a caixa de mensagens. | O painel solicita autenticação ou redireciona para a tela de login. |
| TC05 | Impedir envio sem nome | negativo | 2 | Preencher os demais campos do contato com dados válidos, deixar o nome vazio e enviar. | A mensagem não é enviada e a confirmação de sucesso não aparece. |
| TC06 | Impedir envio sem assunto | negativo | 2 | Preencher os demais campos do contato com dados válidos, deixar o assunto vazio e enviar. | A mensagem não é enviada e a confirmação de sucesso não aparece. |
| TC07 | Não incrementar o contador sem envio válido | negativo | 1, 2, 3 | Anotar o contador no painel, tentar enviar contato sem nome e voltar ao painel. | O contador permanece igual ao valor anotado. |
| TC08 | Exibir os dados informados sem confundir mensagens | borda | 2, 4 | Enviar uma mensagem com nome e assunto únicos, incluindo espaços internos, e consultar a caixa de mensagens. | A confirmação e a entrada na lista correspondem exatamente aos dados enviados. |

SUPOSIÇÕES

- A aplicação é uma interface web e os testes usam pytest, pytest-playwright e a API síncrona do Playwright; o plugin fornece a fixture `page`.
- A constante `BASE_URL` contém a URL base informada. As rotas `/admin`, `/#contact` e `/admin/messages` são suposições deduzidas, pois a história só especifica `/admin`.
- Os seletores são inferidos: campos identificáveis por rótulos acessíveis ou placeholders, links/botões acessíveis com nomes como `Contact`, `Submit`, `Login`, `Messages` e `Logout`. Se a interface real usar outros nomes, os seletores devem ser ajustados.
- O formulário de contato exige nome, e-mail, telefone, assunto e mensagem. Os testes usam valores fictícios válidos; os critérios não especificam telefone, mensagem nem validações exatas.
- O login usa os dados de demonstração `admin` e `password`.
- Para contagem e listagem, cada teste cria uma mensagem com identificador único; assume-se que mensagens ficam persistidas e que o contador reflete mensagens recebidas.
- A ausência de confirmação de sucesso é usada como verificação negativa, pois a história não define o texto de erro nem a apresentação da validação.
- O acesso não autenticado a Messages pode mostrar a tela de login ou redirecionar para `/admin`; ambos são aceitos no TC04.
- Os testes que verificam o contador dependem de uma aplicação isolada ou de que nenhuma outra mensagem seja enviada em paralelo durante a execução.

```python
import uuid

import pytest
from playwright.sync_api import expect


BASE_URL = "https://automationintesting.online/"
ADMIN_URL = BASE_URL.rstrip("/") + "/admin"
MESSAGES_URL = BASE_URL.rstrip("/") + "/admin/messages"


def unique_suffix():
    return uuid.uuid4().hex[:8]


def fill_contact_form(page, name, subject, *, include_name=True, include_subject=True):
    page.goto(BASE_URL)
    page.get_by_label("Name").fill(name if include_name else "")
    page.get_by_label("Email").fill(f"qa-{unique_suffix()}@example.com")
    page.get_by_label("Phone").fill("11987654321")
    page.get_by_label("Subject").fill(subject if include_subject else "")
    page.get_by_label("Message").fill("Mensagem de teste automatizado.")
    page.get_by_role("button", name="Submit").click()


def login_as_admin(page):
    page.goto(ADMIN_URL)
    page.get_by_label("Username").fill("admin")
    page.get_by_label("Password").fill("password")
    page.get_by_role("button", name="Login").click()


def read_message_count(page):
    messages_link = page.get_by_role("link", name="Messages")
    expect(messages_link).to_be_visible()
    import re
    match = re.search(r"\d+", messages_link.inner_text())
    assert match, "Não foi encontrado um número ao lado de Messages"
    return int(match.group())


def test_TC01_enviar_mensagem_valida(page):
    name = f"Visitante {unique_suffix()}"
    fill_contact_form(page, name, f"Assunto {unique_suffix()}")
    expect(page.get_by_text(f"Thanks for getting in touch {name}!", exact=True)).to_be_visible()


def test_TC02_contador_aumenta_apos_envio(page):
    login_as_admin(page)
    before = read_message_count(page)

    name = f"Visitante {unique_suffix()}"
    fill_contact_form(page, name, f"Assunto {unique_suffix()}")

    login_as_admin(page)
    after = read_message_count(page)
    assert after == before + 1


def test_TC03_mensagem_enviada_aparece_na_lista(page):
    name = f"Visitante {unique_suffix()}"
    subject = f"Assunto {unique_suffix()}"
    fill_contact_form(page, name, subject)
    expect(page.get_by_text(f"Thanks for getting in touch {name}!", exact=True)).to_be_visible()

    login_as_admin(page)
    page.get_by_role("link", name="Messages").click()
    expect(page.get_by_text(name, exact=True)).to_be_visible()
    expect(page.get_by_text(subject, exact=True)).to_be_visible()


def test_TC04_caixa_de_mensagens_exige_login_apos_logout(page):
    login_as_admin(page)
    page.get_by_role("link", name="Logout").click()
    page.goto(MESSAGES_URL)

    login_prompt = page.get_by_label("Username")
    admin_route = page.get_by_role("heading", name="Admin")
    expect(login_prompt.or_(admin_route)).to_be_visible()


def test_TC05_envio_sem_nome_nao_e_confirmado(page):
    name = f"Visitante {unique_suffix()}"
    fill_contact_form(
        page,
        name,
        f"Assunto {unique_suffix()}",
        include_name=False,
    )
    expect(page.get_by_text("Thanks for getting in touch", exact=False)).to_have_count(0)


def test_TC06_envio_sem_assunto_nao_e_confirmado(page):
    name = f"Visitante {unique_suffix()}"
    fill_contact_form(
        page,
        name,
        f"Assunto {unique_suffix()}",
        include_subject=False,
    )
    expect(page.get_by_text("Thanks for getting in touch", exact=False)).to_have_count(0)


def test_TC07_envio_invalido_nao_incrementa_contador(page):
    login_as_admin(page)
    before = read_message_count(page)

    fill_contact_form(
        page,
        f"Visitante {unique_suffix()}",
        f"Assunto {unique_suffix()}",
        include_name=False,
    )

    login_as_admin(page)
    after = read_message_count(page)
    assert after == before


def test_TC08_mensagem_com_dados_distintivos_e_preservada(page):
    name = f"  Ana QA {unique_suffix()}  "
    subject = f"Consulta especial {unique_suffix()}"
    fill_contact_form(page, name, subject)

    normalized_name = name.strip()
    expect(
        page.get_by_text(
            f"Thanks for getting in touch {normalized_name}!",
            exact=True,
        )
    ).to_be_visible()

    login_as_admin(page)
    page.get_by_role("link", name="Messages").click()
    expect(page.get_by_text(normalized_name, exact=True)).to_be_visible()
    expect(page.get_by_text(subject, exact=True)).to_be_visible()
```
