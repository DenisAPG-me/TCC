SUPOSIÇÕES

- A única fonte utilizada é a User Story. O código não foi executado contra o sistema; seletores e comportamentos não foram verificados.
- O formulário está diretamente em `https://automationintesting.online/`. Não são presumidas outras rotas.
- Conforme o requisito técnico prevalecente, são necessários `pytest`, `playwright` e o plugin oficial `pytest-playwright`, além do navegador instalado pelo Playwright. A fixture `page` é fornecida exclusivamente pelo plugin.
- Os campos possuem rótulos acessíveis únicos e exatos: `Name`, `Email`, `Phone`, `Subject` e `Message`. O botão de envio possui papel `button` e nome acessível exato `Submit`. Esses seletores são deduzidos e podem precisar de ajuste.
- Cada teste recebe uma página isolada do plugin. O formulário pode ser acessado e enviado sem autenticação, CAPTCHA, consentimento, dados prévios ou etapas adicionais.
- Os campos aceitam `fill()`, inclusive com valores inválidos e acima dos limites. Não há truncamento, máscara ou validação nativa do navegador impedindo o envio dos cenários negativos.
- Para o critério 1, cujos textos exatos não foram fornecidos, presumem-se mensagens contendo `Name may not be blank`, `Email may not be blank`, `Phone may not be blank`, `Subject may not be blank` e `Message may not be blank`.
- As mensagens de erro aparecem como textos visíveis únicos. A busca por trecho permite prefixos ou outros textos no mesmo elemento. Erros adicionais não invalidam os testes.
- Os limites indicados nas mensagens são inclusivos. A rejeição acima dos máximos é inferida dessas mensagens, embora não esteja descrita como cenário explícito.
- Os dados válidos padrão são nome `Ana Silva`, e-mail `ana.silva@example.com`, telefone `119876543210`, assunto `Duvida sobre reserva` e mensagem `Gostaria de saber se ha quartos disponiveis em dezembro.`.
- Telefones são sequências de dígitos e sua validade depende apenas do comprimento descrito. Assuntos e mensagens formados por letras repetidas são aceitos quando respeitam os limites; não são presumidas outras regras de conteúdo.
- A confirmação contém um texto visível único exatamente igual a `Thanks for getting in touch Ana Silva!` e outro exatamente igual ao assunto enviado, preservando seu conteúdo completo.
- Os testes de sucesso verificam apenas a confirmação na interface; entrega de e-mail, persistência e processamento posterior não fazem parte dos critérios.
- Cada cenário inválido mantém os demais campos válidos, exceto TC01 e TC03, que exercitam explicitamente erros simultâneos. TC06 e TC07 combinam limites válidos.
- O arquivo pode ser salvo como `test_contato.py` e executado com `pytest test_contato.py`. Os testes usam as esperas automáticas do Playwright.

```python
from playwright.sync_api import Page, expect

BASE_URL = "https://automationintesting.online/"

VALID_DATA = {
    "name": "Ana Silva",
    "email": "ana.silva@example.com",
    "phone": "119876543210",
    "subject": "Duvida sobre reserva",
    "message": (
        "Gostaria de saber se ha quartos disponiveis em dezembro."
    ),
}

FIELD_LABELS = {
    "name": "Name",
    "email": "Email",
    "phone": "Phone",
    "subject": "Subject",
    "message": "Message",
}

BLANK_ERRORS = (
    "Name may not be blank",
    "Email may not be blank",
    "Phone may not be blank",
    "Subject may not be blank",
    "Message may not be blank",
)

PHONE_ERROR = "Phone must be between 11 and 21 characters."
SUBJECT_ERROR = "Subject must be between 5 and 100 characters."
MESSAGE_ERROR = "Message must be between 20 and 2000 characters."
EMAIL_ERROR = "must be a well-formed email address"


def _submit(page: Page, data: dict[str, str]) -> None:
    """Seletores presumidos: rótulos exatos e botão Submit único."""
    page.goto(BASE_URL)

    for field, label in FIELD_LABELS.items():
        page.get_by_label(label, exact=True).fill(data[field])

    page.get_by_role("button", name="Submit", exact=True).click()


def _submit_valid_variant(page: Page, **changes: str) -> dict[str, str]:
    """Cria dados independentes, sem modificar os valores padrão."""
    data = {**VALID_DATA, **changes}
    _submit(page, data)
    return data


def _expect_error(page: Page, message: str) -> None:
    expect(page.get_by_text(message, exact=False)).to_be_visible()


def _expect_success(page: Page, data: dict[str, str]) -> None:
    expect(
        page.get_by_text(
            f"Thanks for getting in touch {data['name']}!",
            exact=True,
        )
    ).to_be_visible()

    expect(
        page.get_by_text(data["subject"], exact=True)
    ).to_be_visible()


def test_TC01_formulario_vazio(page: Page) -> None:
    _submit(page, {field: "" for field in FIELD_LABELS})

    for message in BLANK_ERRORS:
        _expect_error(page, message)


def test_TC02_telefone_com_10_caracteres(page: Page) -> None:
    _submit_valid_variant(page, phone="1" * 10)

    _expect_error(page, PHONE_ERROR)


def test_TC03_assunto_com_4_e_mensagem_com_19_caracteres(
    page: Page,
) -> None:
    _submit_valid_variant(
        page,
        subject="A" * 4,
        message="M" * 19,
    )

    _expect_error(page, SUBJECT_ERROR)
    _expect_error(page, MESSAGE_ERROR)


def test_TC04_email_malformado(page: Page) -> None:
    _submit_valid_variant(page, email="bad")

    _expect_error(page, EMAIL_ERROR)


def test_TC05_dados_validos_intermediarios(page: Page) -> None:
    data = _submit_valid_variant(page)

    _expect_success(page, data)


def test_TC06_limites_minimos_validos(page: Page) -> None:
    data = _submit_valid_variant(
        page,
        phone="1" * 11,
        subject="A" * 5,
        message="M" * 20,
    )

    _expect_success(page, data)


def test_TC07_limites_maximos_validos(page: Page) -> None:
    data = _submit_valid_variant(
        page,
        phone="1" * 21,
        subject="A" * 100,
        message="M" * 2000,
    )

    _expect_success(page, data)


def test_TC08_telefone_com_22_caracteres(page: Page) -> None:
    _submit_valid_variant(page, phone="1" * 22)

    _expect_error(page, PHONE_ERROR)


def test_TC09_assunto_com_101_caracteres(page: Page) -> None:
    _submit_valid_variant(page, subject="A" * 101)

    _expect_error(page, SUBJECT_ERROR)


def test_TC10_mensagem_com_2001_caracteres(page: Page) -> None:
    _submit_valid_variant(page, message="M" * 2001)

    _expect_error(page, MESSAGE_ERROR)
```
