## CASOS DE TESTE

| ID | Título | Tipo | Critério de Aceitação | Passos | Resultado Esperado |
|----|--------|------|-----------------------|--------|--------------------|
| CT01 | Criar reserva válida | Positivo | CA1 | Gerar nome e sobrenome únicos; Enviar uma reserva com todos os campos preenchidos | Status 200; Identificador inteiro positivo; Dados retornados iguais aos enviados |
| CT02 | Consultar reserva criada | Positivo | CA2 | Criar uma reserva válida; Consultar pelo identificador retornado | Criação bem-sucedida; Consulta com status 200; Todos os campos e tipos preservados |
| CT03 | Consultar identificador inexistente | Negativo | CA3 | Consultar a reserva com identificador 99999999 | Status 404 |
| CT04 | Filtrar pelo nome e sobrenome | Positivo | CA4 | Criar reserva com nome e sobrenome únicos; Listar reservas passando ambos como filtros | Criação bem-sucedida; Listagem com status 200; Lista contém o identificador criado |
| CT05 | Preservar preço zero e depósito não pago | Borda | CA1, CA2 | Criar reserva com preço total zero e depósito pago falso; Consultar pelo identificador retornado | Criação e consulta com status 200; Identificador inteiro positivo; Zero, falso e demais dados preservados |
| CT06 | Preservar acentos e necessidades adicionais vazias | Borda | CA1, CA2, CA4 | Criar reserva com nomes únicos contendo acentos e necessidades adicionais vazias; Consultar pelo identificador; Filtrar pelo nome e sobrenome | Criação, consulta e listagem com status 200; Dados e acentos preservados; Lista contém o identificador criado |

## SUPOSIÇÕES

- A tecnologia escolhida é Python + pytest + requests, pois os critérios tratam exclusivamente de uma API REST. Não há seletores, navegador ou dependências de UI.
- O contrato foi deduzido exclusivamente da User Story, sem acesso ao sistema, à documentação ou à internet. O script não foi executado contra a API.
- Os endpoints presumidos são `POST /booking` para criação, `GET /booking/{bookingid}` para consulta e `GET /booking` para listagem. Os filtros presumidos são os parâmetros de consulta `firstname` e `lastname`, enviados juntos.
- O payload presumido contém `firstname` e `lastname` como strings, `totalprice` como inteiro, `depositpaid` como booleano, `bookingdates` como objeto com `checkin` e `checkout` no formato `YYYY-MM-DD`, e `additionalneeds` como string.
- A criação retorna um objeto JSON com `bookingid` inteiro positivo e `booking` contendo os dados enviados. A consulta retorna diretamente o objeto da reserva. A listagem retorna uma lista de objetos contendo `bookingid`.
- A comparação dos dados exige os mesmos campos, valores e tipos no objeto da reserva, incluindo as datas aninhadas. A ordem das propriedades JSON é irrelevante. Campos extras no envelope de criação e nos itens da listagem são permitidos.
- Criação, consulta e listagem não exigem autenticação. A constante de credenciais usa `None`, e as requisições solicitam respostas JSON.
- Os dados são sintéticos, com datas fixas de 10 a 12 de novembro de 2030. Supõe-se que esse intervalo seja válido no ambiente de execução; as constantes devem ser atualizadas se necessário.
- Preço zero, depósito não pago, nomes com acentos e necessidades adicionais vazias são considerados válidos para os cenários de borda. Essa validade é uma dedução, não uma regra explicitamente estabelecida pela User Story.
- Um sufixo UUID hexadecimal é acrescentado a nome e sobrenome em cada criação. Supõe-se que esses caracteres e comprimentos sejam aceitos e que colisões sejam desprezíveis.
- O identificador `99999999` é considerado inexistente, conforme o exemplo fornecido. Se existir no ambiente, CT03 falhará; não haverá exclusão de reservas para forçar essa condição.
- A reserva fica disponível imediatamente após a criação, inclusive nos filtros. Supõe-se que a listagem filtrada não exija paginação adicional para encontrar o registro criado.
- O corpo e a mensagem da resposta 404 não são validados, pois não foram especificados. Não se presumem códigos para payloads inválidos, limites de tamanho ou datas invertidas.
- Cada teste cria seus próprios pré-requisitos. Não há exclusão posterior, pois o contrato de exclusão e suas permissões não foram fornecidos; as reservas sintéticas permanecerão no ambiente.
- Todas as requisições usam timeout de conexão de 5 segundos e de leitura de 20 segundos, sem repetição automática ou espera artificial. Redirecionamentos não são seguidos, permitindo validar o status do endpoint original.
- O arquivo pode ser salvo como `test_reservas.py` e executado com `pytest test_reservas.py`, em um ambiente com pytest e requests instalados e acesso à URL informada.

## SCRIPT

```python
from copy import deepcopy
from uuid import uuid4

import pytest
import requests


BASE_URL = "https://restful-booker.herokuapp.com"
CREDENTIALS = None
TIMEOUT = (5, 20)
HEADERS = {"Accept": "application/json"}
INEXISTENT_BOOKING_ID = 99999999

BASE_BOOKING = {
    "firstname": "Ana",
    "lastname": "Teste",
    "totalprice": 250,
    "depositpaid": True,
    "bookingdates": {
        "checkin": "2030-11-10",
        "checkout": "2030-11-12",
    },
    "additionalneeds": "Breakfast",
}

ZERO_PRICE_OVERRIDES = {
    "totalprice": 0,
    "depositpaid": False,
}

UNICODE_OVERRIDES = {
    "firstname": "João",
    "lastname": "Conceição",
    "additionalneeds": "",
}


@pytest.fixture
def api():
    with requests.Session() as session:
        session.headers.update(HEADERS)
        session.auth = CREDENTIALS
        yield session


def make_booking(overrides=None):
    payload = deepcopy(BASE_BOOKING)
    if overrides is not None:
        payload.update(deepcopy(overrides))

    suffix = uuid4().hex
    payload["firstname"] = f"{payload['firstname']}_{suffix}"
    payload["lastname"] = f"{payload['lastname']}_{suffix}"
    return payload


def assert_status(response, expected):
    assert response.status_code == expected, (
        f"{response.request.method} {response.url}: "
        f"esperado status {expected}, recebido {response.status_code}. "
        f"Corpo: {response.text[:1000]}"
    )


def read_json(response):
    try:
        return response.json()
    except ValueError as exc:
        pytest.fail(
            f"Resposta não contém JSON válido em {response.url}: "
            f"{exc}. Corpo: {response.text[:1000]}"
        )


def assert_same_data(actual, expected, path="booking"):
    # A comparação de tipos evita aceitar True como 1 ou False como 0.
    assert type(actual) is type(expected), (
        f"{path}: tipo esperado {type(expected).__name__}, "
        f"recebido {type(actual).__name__}"
    )

    if isinstance(expected, dict):
        assert set(actual) == set(expected), (
            f"{path}: campos esperados {sorted(expected)}, "
            f"recebidos {sorted(actual)}"
        )
        for key, value in expected.items():
            assert_same_data(actual[key], value, f"{path}.{key}")
    else:
        assert actual == expected, (
            f"{path}: esperado {expected!r}, recebido {actual!r}"
        )


def create_booking(api, payload):
    response = api.post(
        f"{BASE_URL}/booking",
        json=payload,
        timeout=TIMEOUT,
        allow_redirects=False,
    )
    assert_status(response, 200)

    body = read_json(response)
    assert isinstance(body, dict), "Criação deve retornar um objeto JSON"
    assert "bookingid" in body, "Resposta sem bookingid"
    assert type(body["bookingid"]) is int, (
        "bookingid deve ser inteiro, não booleano ou string"
    )
    assert body["bookingid"] > 0, "bookingid deve ser positivo"
    assert "booking" in body, "Resposta sem booking"
    assert_same_data(body["booking"], payload)
    return body["bookingid"]


def fetch_booking(api, booking_id):
    return api.get(
        f"{BASE_URL}/booking/{booking_id}",
        timeout=TIMEOUT,
        allow_redirects=False,
    )


def list_bookings(api, payload):
    return api.get(
        f"{BASE_URL}/booking",
        params={
            "firstname": payload["firstname"],
            "lastname": payload["lastname"],
        },
        timeout=TIMEOUT,
        allow_redirects=False,
    )


def assert_list_contains(response, booking_id):
    assert_status(response, 200)
    body = read_json(response)
    assert isinstance(body, list), "Listagem deve retornar uma lista JSON"

    returned_ids = []
    for index, item in enumerate(body):
        assert isinstance(item, dict), f"Item {index} deve ser objeto JSON"
        assert "bookingid" in item, f"Item {index} sem bookingid"
        assert type(item["bookingid"]) is int, (
            f"bookingid do item {index} deve ser inteiro"
        )
        returned_ids.append(item["bookingid"])

    assert booking_id in returned_ids, (
        f"Reserva {booking_id} ausente na listagem filtrada: {returned_ids}"
    )


def test_ct01_criar_reserva_valida(api):
    payload = make_booking()

    booking_id = create_booking(api, payload)

    assert type(booking_id) is int
    assert booking_id > 0


def test_ct02_consultar_reserva_criada(api):
    payload = make_booking()
    booking_id = create_booking(api, payload)

    response = fetch_booking(api, booking_id)

    assert_status(response, 200)
    assert_same_data(read_json(response), payload)


def test_ct03_consultar_identificador_inexistente(api):
    response = fetch_booking(api, INEXISTENT_BOOKING_ID)

    assert_status(response, 404)


def test_ct04_filtrar_por_nome_e_sobrenome(api):
    payload = make_booking()
    booking_id = create_booking(api, payload)

    response = list_bookings(api, payload)

    assert_list_contains(response, booking_id)


def test_ct05_preservar_preco_zero_e_deposito_falso(api):
    payload = make_booking(ZERO_PRICE_OVERRIDES)
    booking_id = create_booking(api, payload)

    response = fetch_booking(api, booking_id)

    assert_status(response, 200)
    body = read_json(response)
    assert_same_data(body, payload)
    assert type(body["totalprice"]) is int
    assert body["totalprice"] == 0
    assert body["depositpaid"] is False


def test_ct06_preservar_acentos_e_necessidades_vazias(api):
    payload = make_booking(UNICODE_OVERRIDES)
    booking_id = create_booking(api, payload)

    response = fetch_booking(api, booking_id)

    assert_status(response, 200)
    body = read_json(response)
    assert_same_data(body, payload)
    assert body["firstname"] == payload["firstname"]
    assert body["lastname"] == payload["lastname"]
    assert body["additionalneeds"] == ""

    filtered_response = list_bookings(api, payload)

    assert_list_contains(filtered_response, booking_id)
```
