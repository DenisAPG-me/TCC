CASOS DE TESTE

| ID | título | tipo | critério de aceitação relacionado | passos resumidos | resultado esperado |
|---|---|---|---|---|---|
| CT001 | Login com usuário e senha vazios | negativo | CA01 | Abrir a tela de login e enviar o formulário vazio. | Exibe “Invalid credentials” e permanece na tela de login. |
| CT002 | Login com senha incorreta | negativo | CA02 | Abrir a tela de login, informar `admin` e uma senha incorreta e enviar. | Exibe “Invalid credentials”. |
| CT003 | Login válido e conteúdo do painel | positivo | CA03 | Entrar com `admin` e `password`. | A lista de quartos inclui o quarto 101 do tipo Single e o menu mostra Rooms, Report, Branding e Messages. |
| CT004 | Logout retorna à página inicial pública | positivo | CA03, CA04 | Entrar com as credenciais válidas e clicar em Logout. | Retorna à página inicial pública da pousada. |
| CT005 | Acesso à lista de quartos após logout | positivo | CA03, CA04, CA05 | Entrar, sair e acessar diretamente a lista de quartos do painel. | A tela de login é apresentada novamente. |

SUPOSIÇÕES

1. Os critérios não têm identificadores próprios. Foram nomeados CA01 a CA05 na ordem em que aparecem na User Story, correspondendo aos critérios 1 a 5, respectivamente.
2. A URL base explícita é `https://automationintesting.online/`. Presume-se que a tela de login seja `/admin`, que a lista de quartos seja `/admin/rooms` e que o formulário use campos acessíveis chamados “Username” e “Password”, além de um botão “Login”. Essas rotas e rótulos foram inferidos para a automação e podem exigir ajustes antes do uso no sistema real.
3. Presume-se que a mensagem de falha seja texto visível “Invalid credentials”, que a página inicial pública tenha o título “Shady Meadows B&B” e que o menu e a listagem exponham os textos mencionados no critério. Os seletores por papel/texto refletem essas suposições.
4. A conta de demonstração `admin` / `password` é explícita na User Story e é usada nos casos positivos. O caso CT002 usa `incorrect-password`, inferida como senha inválida.
5. CT005 usa o caminho `/admin/rooms`, inferido para acesso direto à lista. CT004 e CT005 dependem de que o logout encerre a sessão do navegador usado pelo teste.
6. Os casos negativos e de borda aplicáveis estão cobertos pelos envios de credenciais vazias, senha incorreta e acesso direto após logout. Não foram especificados limites numéricos ou entradas de fronteira adicionais.
7. A implementação usa a fixture `page` do pytest-playwright e `expect`, conforme o requisito técnico específico da User Story. O ambiente deve ter `pytest-playwright`, Playwright e Chromium instalados. O código é executável, mas as suposições de rotas, rótulos e textos não comprovam compatibilidade com o sistema real.

```python
import os

import pytest
from playwright.sync_api import expect


BASE_URL = os.getenv("BASE_URL", "https://automationintesting.online/").rstrip("/")
LOGIN_URL = f"{BASE_URL}/admin"
ROOMS_URL = f"{BASE_URL}/admin/rooms"

VALID_USERNAME = "admin"
VALID_PASSWORD = "password"
INVALID_PASSWORD = "incorrect-password"

LOGIN_USERNAME_LABEL = "Username"
LOGIN_PASSWORD_LABEL = "Password"
LOGIN_BUTTON_NAME = "Login"
LOGOUT_BUTTON_NAME = "Logout"
INVALID_CREDENTIALS_TEXT = "Invalid credentials"
PUBLIC_HOME_TITLE = "Shady Meadows B&B"


def open_login(page):
    page.goto(LOGIN_URL)
    expect(page.get_by_label(LOGIN_USERNAME_LABEL)).to_be_visible()
    expect(page.get_by_label(LOGIN_PASSWORD_LABEL)).to_be_visible()


def login(page, username=VALID_USERNAME, password=VALID_PASSWORD):
    page.get_by_label(LOGIN_USERNAME_LABEL).fill(username)
    page.get_by_label(LOGIN_PASSWORD_LABEL).fill(password)
    page.get_by_role("button", name=LOGIN_BUTTON_NAME).click()


def assert_invalid_login(page):
    expect(page.get_by_text(INVALID_CREDENTIALS_TEXT, exact=True)).to_be_visible()
    expect(page.get_by_label(LOGIN_USERNAME_LABEL)).to_be_visible()
    expect(page.get_by_label(LOGIN_PASSWORD_LABEL)).to_be_visible()


def authenticate(page):
    open_login(page)
    login(page)
    expect(page).to_have_url(ROOMS_URL)


def test_CT001_login_com_credenciais_vazias(page):
    open_login(page)
    page.get_by_role("button", name=LOGIN_BUTTON_NAME).click()

    assert_invalid_login(page)
    expect(page).to_have_url(LOGIN_URL)


def test_CT002_login_com_senha_incorreta(page):
    open_login(page)
    login(page, username=VALID_USERNAME, password=INVALID_PASSWORD)

    assert_invalid_login(page)


def test_CT003_login_valido_e_conteudo_do_painel(page):
    authenticate(page)

    expect(page.get_by_text("101", exact=True)).to_be_visible()
    expect(page.get_by_text("Single", exact=True)).to_be_visible()

    for menu_item in ("Rooms", "Report", "Branding", "Messages"):
        expect(page.get_by_text(menu_item, exact=True)).to_be_visible()


def test_CT004_logout_retorna_a_pagina_inicial_publica(page):
    authenticate(page)
    page.get_by_role("button", name=LOGOUT_BUTTON_NAME).click()

    expect(page).to_have_url(BASE_URL + "/")
    expect(page).to_have_title(PUBLIC_HOME_TITLE)


def test_CT005_acesso_a_quartos_apos_logout_exige_novo_login(page):
    authenticate(page)
    page.get_by_role("button", name=LOGOUT_BUTTON_NAME).click()
    expect(page).to_have_url(BASE_URL + "/")
    expect(page).to_have_title(PUBLIC_HOME_TITLE)

    page.goto(ROOMS_URL)

    expect(page).to_have_url(LOGIN_URL)
    expect(page.get_by_label(LOGIN_USERNAME_LABEL)).to_be_visible()
    expect(page.get_by_label(LOGIN_PASSWORD_LABEL)).to_be_visible()
```
